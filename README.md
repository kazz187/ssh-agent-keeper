# ssh-agent-keeper

ssh-agent をすべてのシェルで 1 つだけ共有し、鍵のパスフレーズ入力を 1 回で済ませるためのツールです。

ターミナルが再起動時に複数のウィンドウを一斉に復元するような状況でも、

- ssh-agent が重複して起動しない
- すべてのウィンドウにパスフレーズのプロンプトが出るが、**どれか 1 つで入力すれば残りのウィンドウも自動的に先へ進む**

ようになります。

## インストール

```sh
go install github.com/kazz187/ssh-agent-keeper@latest
```

## 設定

`~/.zshrc` などで次のように評価します。

```zsh
eval "$(ssh-agent-keeper)"
```

`ssh-add` に引数を渡したい場合は `--` の後ろに書きます。

```zsh
eval "$(ssh-agent-keeper -- ~/.ssh/id_ed25519)"
```

| オプション | 既定値 | 説明 |
|---|---|---|
| `-f file` | `~/.ssh-agent` | エージェントの情報を記録する状態ファイル |

## 動作

状態ファイルは `ssh-agent -s` の出力と同じ形式なので、従来どおり `. ~/.ssh-agent` で読み込むこともできます。

1. 状態ファイルを `flock` で排他ロックし、記録されているエージェントが生きているか確認します。PID が存在するだけでなくソケットが応答することまで確かめるので、再起動後に PID が別のプロセスに再利用されていても誤認しません。生きていなければ `ssh-agent` を起動して状態ファイルに記録します。ロックがあるので、同時に起動したシェルが別々にエージェントを起動することはありません。
2. エージェントが鍵を 1 つも持っておらず、標準入力が端末であれば `ssh-add` を実行してパスフレーズを尋ねます。同時に状態ファイルを [fswatcher](https://github.com/fswatcher/fswatcher) で監視します。
3. どれかのウィンドウで `ssh-add` が成功すると、そのウィンドウが状態ファイルを書き直して知らせます。監視していた他のウィンドウはエージェントが鍵を持ったことを確認し、自分の `ssh-add` を止めて先に進みます。
4. 最後に `SSH_AUTH_SOCK` と `SSH_AGENT_PID` を設定するシェルコードを標準出力に出力します。

`ssh-add` はシェルのジョブと同じように端末のフォアグラウンドで実行されます。そのため、プロンプトで Ctrl-C を押すとそのウィンドウでのパスフレーズ入力だけがスキップされ、シェルの起動処理は中断されずに続きます。
